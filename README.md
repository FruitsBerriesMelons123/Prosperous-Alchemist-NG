# Prosperous Alchemist NG

Prosperous Alchemist is an SKSE plugin that calculates the most valuable potion or poison currently craftable from the player's ingredients. It accounts for the alchemy skill, relevant perks, worn Fortify Alchemy equipment, ingredient effects, and optional ingredient protection rules.

![Prosperous Alchemist preview](Prosperous-Alchemist-NG.jfif)

> This repository contains the native plugin source and build configuration. It is not a packaged installer or a complete mod archive.

For installation and gameplay instructions, see the [user-facing guide](docs/USER_README.md).

## Current build state

- The native plugin is an **Address Library** plugin built with CommonLibSSE-NG.
- The Release DLL is self-contained with respect to the third-party C++ libraries used by the project. It does not require `fmt.dll`, `spdlog.dll`, or the dynamic MSVC runtime beside the plugin.
- SKSE, Address Library for SKSE Plugins, and a matching Skyrim runtime are still required. Address Library is not part of this repository or embedded in `alchemist.dll`.
- The minimum runtime payload is the native DLL; the plugin creates an optional `alchemist.ini` with defaults when it starts and does not require an ESP/ESL. `python build.py --package` creates a complete release archive containing the DLL, the optional `alchemist.pdb` diagnostic symbols, `alchemist.ini` when present, all locale and font resources, `COPYING`, `EXCEPTIONS.md`, `docs/USER_README.md`, and the files under `licenses/`. The PDB is optional at runtime and is stored beside the DLL at `SKSE/Plugins/alchemist.pdb`.
- **Localization**: The overlay uses UTF-8 strings, Windows locale detection, BCP 47 locale resources, Unicode Skyrim character events, and a merged multilingual ImGui font atlas. Runtime translations are loaded from `SKSE/Plugins/locales/alchemist.<tag>.json`; optional legally redistributable fonts are loaded from `SKSE/Plugins/fonts`, with English text and Dear ImGui's default font as graceful fallbacks.
- **UI Compatibility**: Operates seamlessly with both Skyrim's native vanilla crafting menu (`RE::CraftingMenu`) and SkyUI; SkyUI is supported but not strictly required.
- **Skyrim VR Presentation**: Intercepts DXGI desktop swap chain present calls, rendering the ImGui overlay to the desktop mirror window. Players in VR can view the window inside their headset using SteamVR Desktop View or overlay utilities (e.g. Desktop+).

## Features

- **Best-recipe recommendation** — Searches combinations of two and three ingredients and recommends the recipe with the highest calculated value.
- **Inventory-aware calculations** — Uses the ingredient forms currently in the player's inventory.
- **Player-aware calculations** — Can use the player's Alchemy skill, Alchemist ranks, Physician, Benefactor, Poisoner, Seeker of Shadows, and worn Fortify Alchemy enchantments.
- **Potion and poison support** — Determines whether a result is a potion or poison from its dominant shared effect and displays the appropriate name.
- **Recipe browser** — Provides search across recipe names, ingredients, and effects; four value/name sort modes; selectable recipe rows; an optional Effects column; and pagination for large result sets.
- **Selected-ingredient filtering** — By default, shows only recipes containing every ingredient currently selected in Skyrim's native alchemy menu. The filter can be disabled in Settings and compares native ingredient FormIDs rather than display names.
- **Ingredient protection** — Optionally excludes quest, crafting, Atronach Forge, Hearthfire, and other valuable ingredients from recommendations. The tracking page is the only in-game control surface for enabling protection, ingredient tracking, and editing the protected list.
- **Custom protection rules** — Adds custom ingredients with an optional inventory threshold and allows individual ingredients to be exempted from protection through the tracking page.
- **Responsive recalculation** — Keeps a long-lived in-memory master recipe cache, incrementally evaluates newly available ingredient combinations, reevaluates cached recipes when player state changes, and performs expensive work on a persistent background worker by default.
- **Safe update handling** — Coalesces rapid requests with a debounce, cancels superseded work, reports progress and completion, and retains a stale cached list with a manual Recalculate action when a slow update is intentionally deferred.
- **Form-accurate recipe identity** — Tracks the actual ingredient forms in each recipe and protection rule so ingredients with duplicate display names remain distinct.
- **Localization support** — Provides translated overlay text through locale resources.
- **Snapshot-based evaluation** — Captures the Skyrim state needed for a calculation before background processing, while menu refreshes and other live UI operations remain on Skyrim's task interface.
- **Diagnostics** — Includes an exhaustive algorithm-completeness report displayed in the Developer Test Hub.

The plugin recommends recipes; it does not automatically craft potions, consume ingredients, modify game records, or change the player's perks.

## How it works

When Skyrim's native alchemy view opens, Prosperous Alchemist displays its D3D11 Dear ImGui main window and:

1. Reads the player's available ingredient forms and inventory counts.
2. Optionally reads the player's current skill, perks, and worn Fortify Alchemy effects.
3. Removes protected ingredients when protection is enabled.
4. Finds every unique pair of remaining ingredients that shares at least one effect.
5. Tests every unique three-ingredient combination, even when it does not add another effect or extend a pair that passed independently.
6. Applies the configured player bonuses and calculates the expected item value.
7. Lists every valid pair and triple once, marking the highest-value result, with its name, effects, value, sorted ingredients, and native ingredient FormIDs retained for identity-sensitive filtering.

The result is recalculated when the ingredient set, tracked player state, or active CACO calculation revision changes. Otherwise, the previous result is reused. A long-lived in-memory master cache survives menu close for the configured duration and supports filtering recipes for smaller ingredient sets without rerunning the full search. New ingredient forms are processed as an incremental delta, while a player-state change reevaluates the cached combinations. Background requests are debounced and superseded work is cancelled; setting `Singlethreaded=1` uses the main-thread calculation path instead.

If a recalculation exceeds the configured stale threshold, the last completed list can remain visible while the plugin marks it as potentially outdated and provides a manual **Recalculate** action. This prevents repeated expensive updates during rapid crafting changes without silently presenting the result as current. The cache and worker state are in memory only; they are not persisted to disk.

The plugin identifies the alchemy view from the runtime-matched native `CraftingMenu` submenu during the menu lifecycle event and fails closed when the expected native menu or submenu is unavailable.

### Cursor and display coordinates

The fake cursor and ImGui mouse input use the same coordinate space. Each rendered frame, the plugin converts the Win32 cursor from screen coordinates to the live Skyrim client area and normalizes it to the current D3D11 swap-chain dimensions, with the client size as a fallback. The mapping contains no monitor-specific or fixed game-resolution values, and saved window geometry is re-clamped when the live render size changes. The cursor tip uses the native SkyUI cursor origin and no guessed pixel offset is applied. This overlay cursor path is separate from Skyrim's camera/input sensitivity and does not change the game's native mouse sampling.

### Result format

A successful recommendation contains:

```text
Potion of Fortify Something: effect description(s)
 Value: 123
Ingredient A, Ingredient B, Ingredient C
```

Potion and poison results use the built-in `Potion of` and `Poison of` prefixes. When CACO renaming is active, its quality and secondary-effect text is retained while the built-in type prefix is applied.

Ingredient names are sorted alphabetically in the displayed recipe. Effect descriptions have their magnitude and duration placeholders replaced with the calculated values.

### Recipe browser controls

The browser search matches recipe names, displayed ingredient names, and effect descriptions. The sort menu provides four modes: value descending, value ascending, name ascending, and name descending. Enable **Effects** to add the calculated effect descriptions as a table column. Click a recipe row to select it; clicking elsewhere in the browser clears the selection. The selected row remains selected when filtering or sorting can still identify it by its ingredient details.

Large result sets are divided into navigable pages. Search and sort changes return to the first page, while selected-ingredient changes try to keep the selected recipe visible. The browser excludes results whose displayed value is below one.

When `FilterPotionsBySelectedIngredients=1` (the default), the browser reads the native alchemy menu's selected ingredient entries and keeps recipes containing **all** of their distinct native forms. With no ingredients selected, the full calculated list is shown. This filter affects the displayed list only; it does not change the calculation or consume ingredients.

## Calculation model

The plugin uses the effect data exposed by Skyrim's ingredient and magic-effect records. For effects whose magnitude or duration is affected by alchemy skill, it applies the following base calculation:

```text
calculated value = base value
				  × (4 + (Alchemy skill / 5 × 0.1))
				  × (1 + Alchemist ranks × 0.20)
				  × (1 + Fortify Alchemy / 100)
```

The same player factors are applied to magnitude and duration when the effect supports them. The relevant additional bonuses are:

- **Physician** — Multiplies Restore Health, Restore Magicka, and Restore Stamina magnitude and duration by 1.25.
- **Benefactor** — Multiplies beneficial potion effects by 1.25.
- **Poisoner** — Multiplies harmful poison effects by 1.25.
- **Seeker of Shadows** — Multiplies calculated magnitude and duration by 1.10.
- **Purity** — When player state is enabled, potions retain beneficial effects and remove harmful effects, while poisons retain harmful effects and remove beneficial effects before the item value is calculated.

For each effect, the estimated value is calculated from its base cost, magnitude, and duration:

```text
base cost × magnitude^1.1 × (duration / 10)^1.1
```

When an effect has only magnitude or only duration, the available component is used. If the same effect exists on multiple ingredients, the implementation keeps the higher-cost version for the recipe calculation.

The recipe's shared effect with the highest calculated cost determines the result type:

- Beneficial dominant effect → **Potion**
- Harmful dominant effect → **Poison**

The displayed value is the calculated value rounded down to a whole number. This is a recommendation based on the plugin's calculation model and should not be treated as a guarantee for every game configuration or modded effect.

## Prediction parity harness

`potion_prediction_test.py` is a standalone Python model of the value-bearing prediction pipeline in `alchemist/include/main.h` and `alchemist/CACO/CACO.h`. Its first purpose is to reproduce the current SKSE plugin, while its recorded investigation changes may intentionally diverge from the native helper until synchronized in-game evidence justifies a C++ update. It reads the committed `ingredients-vanilla.csv` or `ingredients-caco.csv` by default and the managed external-mod snapshots in `alchemist.ini`, then accepts player state, CACO-native perk entry multipliers, and explicit command-line overrides for values that are not present in the ingredient exports. Use `--vanilla-csv` or `--caco-csv` when testing another explicit snapshot; the harness does not search the deployed plugin directory for ingredient data. For CACO duration behavior, the model distinguishes CACO's explicit `MagicAlchDurationBased` keyword from ordinary exported duration-affecting records such as Light and Spell Absorption; this keeps the Python investigation model aligned with the CACO behavior observed in confirmed captures.

The four `potions-predicted-*.csv` files are current-plugin regression fixtures for vanilla, CACO-only, Alchemy Plus-only, and combined modes. The built-in self-tests use the supplied level-15/perk matrix and verify the recipes that can be represented by the exported records. `Blue Mountain Flower,Wheat` is intentionally absent from the CACO fixtures when it does not form a potion.

The potion-observations export is diagnostic-only: it records each positive potion inventory event, the native ingredient selection sequence when the alchemy menu is still readable, ordered container-event evidence, immediate potion value/effects, and the external-mod settings at capture time. The capture remains active for a fixed 10-second grace period after the alchemy menu closes so asynchronous CACO re-add events can be recorded without changing normal alchemy handling; selection order is normally unavailable for those delayed events, so export it after the craft and any CACO adjustment have finished.

Unstable menu-versus-inventory observations are kept separately in `potion-order-dependent-observations.csv` with the investigation notes in `potion-order-dependent-observations.md`. The confirmed-fixture checker validates those rows, reports them as diagnostic-only, and excludes them from expected-value scoring; use `--order-dependent-csv` to select another diagnostic file. Do not add a row to `alchemist.potions-confirmed.csv` when CACO's asynchronous post-craft adjustment may have changed the potion between the menu capture and the later inventory check.

Run the deterministic harness tests from the repository root:

```powershell
python potion_prediction_test.py --self-test
```

The current observed-craft accuracy gate is:

```powershell
python potion_prediction_test.py --check-confirmed-csv
```

This gate scores the explicitly confirmed rows in `links/alchemist.potions-confirmed.csv`, including their native ingredient-selection order. The plugin also maintains `alchemist.potions-confirmed-all.csv` for all captured rows and `alchemist.potion-observations.csv` for diagnostic inventory/potion events. Files generated by the game or plugin (such as these logs and `potions-predicted-*.csv.zst`) are authoritative observation logs and must never be manually edited or script-patched; they are re-generated directly by the game or plugin in-game to verify algorithm accuracy. Backing up or moving a log before a new capture is allowed.

By default, the harness reads `alchemist.ini` next to the configured deployed DLL. If that file is unavailable, it falls back to the repository template; use `--alchemist-ini` to select a different snapshot. The active `[Profile N]` section contains the managed player, CACO, and Alchemy Plus snapshots, so the four paths are selected automatically: vanilla, CACO, Alchemy Plus, or CACO plus Alchemy Plus. Explicit `--caco-enabled` and `--alchemy-plus-enabled` flags override snapshot-presence detection, and all other explicit setting flags override their profile or JSON values. CACO's six zero-based duration selectors, no-stacking flag, potion-handling flag, and XP multiplier are loaded from the active profile's `CACO` snapshot; use the `--caco-*-duration`, `--caco-restore-effects-do-not-stack`, `--caco-disable-all-potion-handling`, and `--caco-alchemy-xp-multiplier` options to override them. CACO-native perk entry-point multipliers remain available with `--caco-*-multiplier`. The active profile's `AlchemyPlus` JSON is used for all supported value-affecting settings and retains other AP settings without discarding them; use `--alchemy-plus-config` to replace it or the `--ap-*` options to override individual rounding values.

## AlchemyPlus compatibility

Prosperous Alchemist passively detects `AlchemyPlus.dll` during SKSE input-loaded initialization. When the DLL is present, it reads `SKSE/Plugins/AlchemyPlus.json` through Skyrim's virtual resource system, so Mod Organizer 2 virtualization is supported. A JSON file by itself does not enable compatibility: the adapter remains inactive unless a supported setting is valid and enabled. When AlchemyPlus is absent, not loaded, missing its JSON file, or has supported settings disabled, the existing Prosperous Alchemist calculation path is unchanged.

The supported prediction settings are:

| AlchemyPlus setting | Supported behavior |
| --- | --- |
| `roundedPotency.enabled` | Applies the configured strict `value > threshold` rounding to predicted magnitude and duration after Prosperous Alchemist's effectiveness calculation and before predicted effect cost calculation. Duration follows AlchemyPlus's native integer storage conversion. |
| `roundedPotency.magnitudeThreshold` / `magnitudeMult` | Configures the global magnitude threshold and positive rounding multiple. |
| `roundedPotency.durationThreshold` / `durationMult` | Configures the global duration threshold and positive rounding multiple. |
| `roundedPotency.overrides` | Resolves valid `plugin\|hex-form-id` effect identifiers and applies valid per-effect magnitude or duration threshold/multiple overrides. Invalid identifiers and values are ignored safely. |
| `impureCostFix.enabled` | For the predicted dominant poison classification, matching hostile effects add cost and opposing effects subtract cost; enabled impure totals are clamped at zero and truncated like AlchemyPlus's `costOverride`. |

The adapter does not install AlchemyPlus hooks, call its DLL, modify Skyrim records, or reproduce its known-failure menu patch, crafted names/models, mixture translations, or exemplar selection. The implementation was developed against AlchemyPlus revision `2c62c0a201c07884be4d6c13e5211b186fa66827`. Exact native crafted-value parity, especially poison classification for mixed effects, remains unverified until the in-game comparison matrix is run.

## CACO compatibility

Prosperous Alchemist detects `Complete Alchemy & Cooking Overhaul.esp` or `.esm` during the `kDataLoaded` lifecycle message and keeps the compatibility implementation in `alchemist/CACO`. It scans the loaded full/light plugin collections and accepts the documented `Update.esm` local FormIDs as fallbacks, which supports CACO installations where records are exposed through the legacy update file. The adapter is reported as detected when the plugin or recognizable records are present, but it is active only when a calculation source and the two live Skyrim alchemy game settings resolve. Optional lists, handling globals, and individual duration variants are resolved independently; missing ones disable only their dependent behavior, and a missing duration variant falls back to the source ingredient effect. If no valid active source can be established, the existing non-CACO calculation remains unchanged.

The evaluator supports four independent configurations:

- **Vanilla Skyrim** — uses the ordinary Skyrim record and effectiveness calculation.
- **Alchemy Plus only** — uses the vanilla calculation, then applies Alchemy Plus potency rounding and impure-cost behavior when those settings are enabled.
- **CACO only** — uses CACO's live effect records, ingredient position lists, game settings, perk entries, and optional post-processing.
- **Alchemy Plus + CACO** — selects the CACO calculation automatically, applies Alchemy Plus rounding to the CACO-constructed potency before the pre-adjustment gold value is formed, and applies Alchemy Plus's impure-cost correction before CACO's optional 20% impure-potion adjustment.

The two compatibility adapters are detected independently; Automatic mode composes them instead of choosing one and silently discarding the other.

For CACO recipes with multiple shared effects, the evaluator retains mixed beneficial/harmful effect sets, applies CACO's mixed-potion perk and impure gates where the live records enable them, and uses Crucible exemplars only for pure one-effect results. The Python investigation model treats CACO's explicit duration keyword as distinct from ordinary loaded-record duration flags; this matters for effects such as Light and Spell Absorption. Invalid or non-finite live inputs are rejected safely rather than converted into fabricated values.

The adapter reads CACO's live records and settings instead of using a second hardcoded ingredient or magic-effect cost table:

| CACO behavior | Prediction behavior |
| --- | --- |
| Rebalanced magic-effect and ingredient records | Uses the loaded ingredient effect magnitude, duration, flags, keywords, and active record base cost. |
| Restore/Damage Health, Magicka, and Stamina duration selectors | Reads the six CACO duration globals, checks the effect-position FormLists, and resolves the selected 1-, 5-, or 10-second magic-effect variant before the ordinary estimate is calculated. CACO's `MagicAlchResistDisease_CACO` metadata is also associated with the Restore Health selector because its exported 1-, 5-, and 10-second ingredient records otherwise have no standard family keyword. |
| Impure Potion Handling | When handling is enabled, `CACO_OptionImpurePotions` is enabled, and the resulting effects contain both `MagicAlchBeneficial` and `MagicAlchHarmful`, reduces every duration-based duration and other magnitude using CACO's truncating 20% operation. The displayed gold value is assigned separately as `int(floor(C_pre) × 0.2)`; it is not recalculated from the weakened effects. |
| Alchemy Plus + CACO | In Automatic mode, applies Alchemy Plus's configured potency rounding to the CACO-resolved effect input before effect ordering and gold aggregation. If both impure-cost features are enabled, Alchemy Plus's signed/truncated total is the CACO pre-adjustment value before CACO's 20% operation. |
| Crucible replacement | For a pure one-effect result, resolves `CACO_AlchemyEffectsList` and `CACO_AlchemyAllPotionList`, selects the matching `Potion0`–`Potion4` quality (or Cure Disease/Cure Poison), and uses the authored replacement form's gold value. |
| Potion Renaming and Reweighting | Preserves CACO's quality and secondary-effect naming while applying the built-in potion or poison type prefix; one-, two-, and three-or-more-effect weight rules are mirrored when the corresponding Potion Handling options are enabled. |
| Kryptopyr's Automated Patches | Supports ingredient replacements in patches such as `cc-rarecurios_caco_patch.esp` (where Creation Club `Aloe Vera Leaves` `0x0060D0` is replaced by CACO's `Aloe Vera` `0x00A100AD`), dynamically evaluating whichever loaded ingredient variant is present in the player's active load order. |

CACO 3.0 disables Potion Handling by default. In that configuration the duration-record and Crucible paths remain available, while the impure, rename, and reweight predictions remain disabled until their live CACO options are enabled. The native Skyrim crafting code does not expose a safe public operation for constructing every hypothetical candidate potion, so ordinary multi-effect values remain estimates based on the loaded records; no active crafting menu state is mutated to obtain them.

### Known CACO Plugin Issues & Workarounds

- **CACO Alchemist Perk Condition Bug**: In `Complete Alchemy & Cooking Overhaul.esp`, CACO overrides vanilla Skyrim's `Alchemist00` through `Alchemist100` perk entries. CACO attached an engine condition to all of its modified perk entries requiring `CACO_OptionDisableAllPotionHandling == 0`. When CACO's scripted potion handling is disabled (`DisableAllPotionHandling = 1`, which is the standard recommended mode), this condition evaluates to `FALSE` in Skyrim's engine, disabling CACO's perk entries without restoring vanilla Skyrim's Alchemist perk rank multipliers (ranks 1–5). As a result, in stock CACO with `DisableAllPotionHandling = 1`, Alchemist perks would be ignored by the engine unless patched.
- **Hardcoded Workaround**: To ensure that Prosperous Alchemist correctly predicts in-game potion values for end-users when `DisableAllPotionHandling = 1`, the prediction engine explicitly falls back to the player's vanilla Alchemist perk rank multiplier (`player.fallback_alchemist_multiplier()`). This hardcoded workaround is documented in `potion_prediction_test.py` and `alchemist/include/main.h` so that predictions match actual in-game crafted values.

## Configuration

The plugin reads this file when it loads if it exists:

```text
Data/SKSE/Plugins/alchemist.ini
```

If the file is missing, the plugin creates it with the default settings during startup. The top-level `[Profiles]` section is always serialized first and maps each unique nonzero native Skyrim Character ID to the last-used `[Profile N]`, such as `123456 = Profile 1`. Every profile-scoped Prosperous Alchemist setting is stored in its profile, including its player-editable `ProfileName`, native Skyrim `CharacterID`, visible character identity, calculation, tracking, developer, localization, window, and external-mod snapshot values. Restart the game after editing the file so the plugin loads the new values.

When SKSE reports a new game or begins loading a save, the plugin waits for a usable native Character ID and visible identity before selecting a profile. An exact Character ID mapping is restored automatically, including the last-used profile when several profiles belong to the same character. If the Character ID is not mapped, the plugin automatically creates and binds a new blank profile for that character. A profile belonging to another Character ID cannot be selected for the current character unless it has `singleprofile=1`.

Automatic creation uses immutable application defaults for every setting and resets character-specific tracking; values customized in another profile, including `developer`, are never used as blank-profile defaults. From Settings, **Create blank profile** uses the same defaults, while **Create from profile** opens a scrollable source list instead of cloning immediately. Each source entry shows its profile name and index, character identity, completed and marked tracking requirements, protected effects, and custom protected ingredients; select the intended profile and confirm to create the copy. The copy keeps the source profile's calculation settings, tracking preferences, developer mode, language, and window layout, but resets the identity, protected ingredients, protected effects and counts, tracking requirements, and managed player/external-mod snapshots. This lets a user customize additional profiles without inheriting another character's inventory or quest state. Profile selection and all profile data are persisted only in `alchemist.ini`; no Skyrim save data is modified.

Skyrim's native `BGSSaveLoadManager::currentCharacterID` is the authoritative persistent character key. After a save load, an exact nonzero Character ID mapping is selected automatically. If there is only one unbound profile, the plugin silently binds it to the first usable character; any other unmapped character receives a new blank profile automatically. Profile names are separate from character identities, must be non-empty, and must be unique case-insensitively; the active profile name can be changed from Settings, but a duplicate or failed name save leaves the existing profile unchanged. The Settings profile area is always available, including when only one profile exists, and allows direct switching between profiles already bound to the current Character ID, blank or cloned profile creation, and deletion of a non-active profile after confirmation. The active profile and the last remaining profile are protected. Unresolved load/new-game transitions do not calculate recipes or write player, CACO, Alchemy Plus, tracker, or window data to the persisted profile. The previous profile format may be migrated when all recognized values are valid; legacy `Current`/`NewGame` metadata, old profile flags, and legacy `[Profiles]` metadata are converted into the Character ID mapping and removed on the next successful save. Unknown sections, invalid typed values, invalid tracking or snapshot JSON, duplicate profile indices or names, and other structurally malformed files are not partially recovered. The malformed file is copied to the first unused `alchemist.backup.ini`, `alchemist.backup2.ini`, and so on, then `alchemist.ini` is replaced with a clean default profile-only file. Normal saves are written to a temporary file and replace the live INI only after the complete profile document is ready; a failed replacement leaves the previous file in place.

### External mod snapshots

Whenever the native alchemy table is opened, the plugin refreshes the current external-mod settings before recipe recalculation. These snapshots are stored as JSON values inside the active `[Profile N]` section:

- `CACO` records the MCM settings that affect Prosperous Alchemist’s prediction inputs: the six zero-based duration selectors, no-stacking state, potion-handling toggle, and Alchemy XP multiplier. CACO duration value `0` means its first `1 SEC` choice, followed by `1` for `5 SEC` and `2` for `10 SEC`. The no-stacking value is read from the live CACO restore-effect records because CACO keeps this MCM value as a Papyrus script variable rather than a global. The vampire restore-health toggle is not persisted because CACO uses it only to decide whether restore-health effects work on vampires, not to change generated potion cost or magnitude.
- `AlchemyPlus` records a canonical configuration JSON value copied from `SKSE/Plugins/AlchemyPlus.json`. The JSON form preserves nested settings, exemplar arrays, and per-effect overrides without requiring a separate hardcoded schema.

These profile keys are maintained by the plugin and should not be edited as primary settings. They are updated only when their on-disk values differ and are cleared for a newly created profile.

When the native alchemy menu is open, the plugin captures the player inventory before crafting. After a craft, it identifies the new alchemy item and consumed ingredients from the inventory delta, then appends a complete confirmation row to `alchemist.potions-confirmed.csv` beside `alchemist.ini` before refreshing the managed INI snapshot. Rows contain the active mode, sorted ingredients, actual item value, player alchemy inputs, perk flags, serialized external-mod settings, and consumed ingredient `ingredient_details` with FormIDs and counts, keeping confirmations with different forms, mods, perks, and settings distinguishable. New rows also contain the native `ingredient_selection_order` sequence with FormIDs and localized names when the menu state is available; the sorted fields remain the prediction-matching representation, and older confirmation rows remain readable with an unavailable selection-order field. Diagnostic confirmation rows also include the crafted potion FormID, cost override, and serialized `crafted_effects` values captured from that same runtime `AlchemyItem`; with CACO post-craft handling enabled, a recorder row can still represent the pre-adjustment item while the later inventory contains the re-added adjusted item, so those observations belong in the separate diagnostic file until both stages are synchronized.

### Profile settings

| Setting | Default | Description |
| --- | ---: | --- |
| `CharacterID` | `0` | Native unsigned 32-bit Skyrim Character ID stored in each `[Profile N]`; `0` means the profile is not yet bound. The top-level `[Profiles]` section maps each nonzero ID to its last-used profile. |
| `ProfileName` | `Profile N` | Player-editable profile label in the active `[Profile N]` section. It must be non-empty and unique case-insensitively across all profiles; visible character identity is stored separately in `Name`, `Race`, `RaceID`, and `Gender`. |
| `developer` | `0` | Set to `1` to show the Developer Test Hub controls. Keep it at `0` during normal gameplay. |

| `IgnorePlayer` | `0` | Uses the player's skill, perks, and worn Fortify Alchemy equipment when calculating values. Set to `1` to ignore player alchemy state. The ingredient list still comes from the player's inventory. |
| `ProtectIngredients` | `0` | Enables the unified ingredient protection and tracking system. When enabled, it protects the configured list, enough ingredients for one of every loaded craftable item, selected ingredient effects, and unfinished tracking requirements. The default is disabled; set to `1` to enable it. |
| `Singlethreaded` | `0` | At `0`, recipe evaluation uses worker threads; at `1`, calculation runs single-threaded on the main thread. |
| `FilterPotionsBySelectedIngredients` | `1` | Filters overlay potion rows to recipes containing every ingredient currently selected in the Skyrim alchemy menu. With no ingredients selected, all calculated potions are shown; the selected potion remains selected if the filter temporarily hides it. |
| `CacheDurationSeconds` | `180` | Keeps the in-memory master recipe cache available after the alchemy menu closes for this many seconds. Set to `0` to expire it immediately; this does not write cache data to disk. |
| `StaleRecalculateThresholdMs` | `500` | When the last calculation took longer than this many milliseconds, allows the existing list to remain visible as stale during subsequent requests and shows a manual **Recalculate** action. Set to `0` to disable this slow-calculation guard. |
| `CraftDebounceMs` | `400` | Waits this many milliseconds after a non-forced recalculation request before starting background work, coalescing rapid inventory/crafting changes. |
| `ProtectedIngredients` | empty | Comma-separated ingredient names, editor IDs, or hexadecimal FormIDs. Each entry can optionally use `entry\|count` to keep that many copies protected. | `ProtectedEffects` | `MagicAlchFortifyEnchanting,MagicAlchFortifySmithing` | In the active `[Profile N]`, a comma-separated list of loaded ingredient effects whose ingredients should be protected. String settings are intentionally comma-delimited. Do not add additional commas to an individual value. Ingredient and effect names and editor IDs are matched case-insensitively; FormID entries use hexadecimal identifiers without a plugin name. Picker-created `formid:0x...` values are exact record identities, while unprefixed legacy hexadecimal values retain their load-order-tolerant matching behavior.

### In-game settings

While the alchemy overlay is open, select **Settings** to edit the active profile's calculation, developer, localization, window, and advanced diagnostic options through the graphical interface. The profile selector, rename, creation, and deletion controls are always shown at the bottom of Settings, including when only one profile exists. The active profile selector switches directly only to a profile already bound to the current native Character ID, unless `singleprofile=1` is active; the lowest-numbered flagged profile remains forced and other profile selections are rejected. The creation controls explain the blank-versus-clone behavior and reset character-specific data when cloning. The profile deletion controls require a second confirmation and only permit deleting a non-active profile; the active and last remaining profiles cannot be deleted. Ingredient tracking and all protection controls are on the **Track** page only. The tracking page uses one protection/tracking setting that is disabled by default, dynamically lists ingredient effects, reserves the ingredients needed to craft one of every loaded ingredient-bearing craftable item, and provides a unified clickable ingredient summary with Custom, Quest, Craftable, and Effect protection columns. Summary rows use exact IngredientItem FormIDs internally, keep the current Skyrim-localized display name, and show an identity suffix so duplicate names do not merge. Atronach Forge detections use the loaded recipe and index-aligned result form lists, so their source names show the actual game-record output such as `Atronach Forge: Staff of Flame Atronach`; unmatched result records use a generic `Atronach Forge` source rather than a misleading root label. Each selected effect can protect all matching copies or a finite quantity per ingredient; clicking an ingredient opens all of its craft, effect, quest, and manual detections with independent finite-quantity or protect-all controls. Completed quests are automatically marked complete and excluded from the protected ingredient list. Detailed detection, manual requirement, quest metadata, quest debugging, and Atronach Forge controls are under the closed-by-default **Detect requirements** expander, which is shown only when the active profile's `developer=1`. The Settings page also exposes the master-cache duration, stale-recalculation threshold, craft debounce delay, and selected-ingredient filter. The **Use single-threaded calculation** option uses multithreaded worker-thread evaluation by default; selecting it runs recipe evaluation on the main thread. Changes are saved to the active `[Profile N]` section automatically, and **Reset all settings** restores the declared defaults for that profile.

## Developer Test Hub

The optional Developer Test Hub is hidden unless the active profile's `developer=1` is set in `alchemist.ini` before starting Skyrim. It is intended for controlled compatibility and regression testing, not normal gameplay. The **Test** button opens the hub beside the recipe list while the native alchemy menu is open.

Hub operations run through Skyrim's task interface and deliberately change the real player state or inventory. The hub does not capture or restore player state, and changes remain after the crafting menu closes; use Skyrim's built-in save/load system to preserve or revert test changes. Provisioning, modifier, and inventory operations recalculate the overlay and refresh the native alchemy submenu after completion; inventory events raised during an active hub task are coalesced to avoid an intermediate recalculation. Explicitly provisioned fixtures remain until removed.

  The **Autoprovision configured ingredients** operation is retained for compatibility but `autoprovision` in `alchemist.ini` is obsolete; use the standard `pat <mode>` test commands for current automated setup. The legacy operation reads the active profile's comma-separated value and adds each requested form up to the test target quantity. An entry may be a localized/display name, an exact raw ingredient FormID such as `0xFE004819`, or a readable qualified selector such as `Roobrush@0xFE004819`. Name-only entries provision every loaded playable form with that name; qualified and raw FormID entries provision only the exact loaded form, which avoids ambiguity when duplicate ingredient names are present. The operation accepts forms without a display name when they are selected by FormID and reports invalid or unavailable selectors in the hub status message. If ingredients are provisioned (via the Developer Test Hub or in-game console commands) while already inside the alchemy menu, press **F** while the native Alchemy Lab UI is focused to refresh and display the newly provisioned ingredient list without exiting the lab.

The **Algorithm completeness** test evaluates all loaded ingredient pairs and triples through Vanilla, Alchemy Plus, CACO, and Automatic paths and displays the totals in the Developer Test Hub. Comparison records created in the hub remain in memory until they are removed or the game process exits; the explicit CSV export controls write ingredient, prediction, and potion-observation diagnostics next to the deployed DLL. The potion-observation export includes the native ingredient selection sequence while the menu is readable, plus ordered inventory-event evidence and the immediate potion state; delayed post-menu CACO events normally have no selection sequence.

### Default protected ingredients

The default `ProtectedIngredients` value is empty, so no static ingredient list is protected automatically. `MagicAlchFortifyEnchanting` and `MagicAlchFortifySmithing` are the stable editor IDs for the default Fortify Enchanting and Fortify Smithing selections in each `[Profile N]`; selected effects protect all matching copies initially, and their effect rows can change the default quantity per ingredient. Localized effect names and FormID keys are also accepted, but editor IDs are recommended for portable configuration. Each ingredient's detail window can still change an individual effect detection to a finite quantity. Protection and tracking are disabled by default through `ProtectIngredients=0`; enable the setting on the in-game **Track** page when desired. **Reset all settings** restores these defaults for the active profile.

- Skyrim Special Edition/Anniversary Edition or VR on Windows.
- A supported Skyrim SE/AE/VR game runtime.
- Skyrim's native alchemy/crafting menu. SkyUI is optional and supported.
- SKSE matching the installed game runtime.


## Building from source

The current plugin build is the standalone CMake project at [`alchemist`](alchemist). CommonLibSSE-NG is consumed from an independent checkout configured by `COMMONLIBSSE_SOURCE`, `COMMONLIBSSE_BUILD_DIR`, and `COMMONLIBSSE_INSTALL_DIR`; it must be configured against a static vcpkg triplet so the resulting Release DLL has no `fmt.dll` or `spdlog.dll` dependency.

`build.py` is the only supported project build entry point. It configures the CMake project with the Ninja generator, builds the single `Release` configuration, and deploys the resulting DLL when local paths are configured; the repository no longer uses or generates solution/project entry files.

### Build prerequisites

- Visual Studio Build Tools with the **MSVC v143 x64/x86 build tools** component and a Windows SDK.
- CMake 3.21 or later. Either on `PATH` or set `CMAKE_DIR` in `config.py` to its `bin` directory.
- Ninja. Either on `PATH` or set `NINJA_DIR` in `config.py` to its directory.
- Python 3.10 or later on `PATH`.
- `md2nexus` for `--package`, with its executable path set as `MD2NEXUS` in `config.py` and `user-paths.md`.
- A reusable vcpkg checkout at `VCPKG_ROOT`, with the CommonLibSSE-NG manifest dependencies installed into the manifest-specific `VCPKG_STATIC_INSTALL_ROOT\x64-windows-static` prefix (see below). The tool/cache root may be shared by compatible consumers; installed prefixes remain manifest-, triplet-, compiler-, and ABI-specific.
- Network access during the first dependency provisioning, or populated vcpkg/CMake caches, so Dear ImGui and CommonLibSSE-NG's optional instruction-decoder dependency can be downloaded.
- An independent CommonLibSSE-NG checkout and its nested OpenVR submodule, initialized recursively. The checkout path is `COMMONLIBSSE_SOURCE` in `config.py`.

### Build with `build.py`

If the external CommonLib checkout was not cloned recursively, initialize its nested dependencies:

```powershell
git -C <external CommonLibSSE-NG checkout> submodule update --init --recursive
```

Copy the ignored local path files from their tracked templates and replace the placeholders with paths for the local machine:

```powershell
Copy-Item config.example.py config.py
Copy-Item user-paths.example.md user-paths.md
```

The static vcpkg location must be the same in `config.py` and `user-paths.md`. If vcpkg is not already installed, clone it and run its bootstrap script:

```powershell
git clone https://github.com/microsoft/vcpkg
.\vcpkg\bootstrap-vcpkg.bat -disableMetrics
```

Install the CommonLibSSE-NG manifest dependencies into the static triplet, setting `--x-manifest-root` to the external checkout and `--x-install-root` to the `vcpkg-packages` directory inside the repository root:

```powershell
$commonlib = "<external CommonLibSSE-NG checkout>"
.\vcpkg\vcpkg.exe install `
	--x-manifest-root=$commonlib `
  --x-install-root=vcpkg-packages `
  --triplet=x64-windows-static `
  --feature-flags=manifests
```

Then set `VCPKG_STATIC_DIR` in `config.py` and `user-paths.md` to `<repository root>\vcpkg-packages\x64-windows-static`.

Build and deploy the plugin:

```powershell
python build.py
```

To create a release distribution zip archive after building and deploying:

```powershell
python build.py --package
```

Packaging also converts `docs/USER_README.md` with the configured `md2nexus` executable and writes the Nexus-ready description to:

```text
dist/Prosperous-Alchemist-NG-nexus-description.bbcode.txt
```

The conversion runs before the ZIP is created. Packaging fails if `MD2NEXUS` does not point to an existing executable, conversion fails, or the generated description is empty; this prevents stale Nexus content from being mistaken for a fresh release.

The resulting DLL is:

```text
build-alchemist/alchemist.dll
```

The wrapper first configures, builds, and installs CommonLibSSE-NG into the external `COMMONLIBSSE_BUILD_DIR` and `COMMONLIBSSE_INSTALL_DIR` paths, then configures the plugin with that installed package and the external `VCPKG_STATIC_DIR`. It exports the reusable vcpkg root/cache settings to child processes but never treats the tool root as a package prefix. It configures CMake with `Ninja`, sets `CMAKE_BUILD_TYPE=Release`, cleans only plugin outputs, builds it once, and deploys the DLL and bundled locale JSON resources to the directory containing `DLL_DEPLOY`. It validates that the build artifact is newer than the recorded build start and that the deployed DLL has the same timestamp and SHA-256 hash. CommonLibSSE-NG's build/cache/package outputs remain outside this repository, while the plugin's consumer-specific CMake/Ninja state remains under `build-alchemist`.

Use `python build.py --build-dir <directory>` to select a different repository-relative build directory, `python build.py --cmake <path-to-cmake>` when CMake is not on `PATH`, or `python build.py --package` to generate `dist/Prosperous-Alchemist-NG-v<major>.<minor>.<patch>.zip` from `MYFP_VERSION_MAJOR`, `MYFP_VERSION_MINOR`, and `MYFP_VERSION_PATCH` in `alchemist/include/version.h`. The beta component is not included in the public archive filename. The wrapper does not accept a configuration argument; Debug, RelWithDebInfo, and MinSizeRel builds are not supported.

### Build the local SKSE checkout

`build-skse.py` is a separate helper for the legacy SKSE source checkout and does not build or deploy `alchemist.dll`. It builds the existing `src/skse64/skse64.sln` with the optimized `Release_VC142|x64` solution configuration, requests MSVC program-database compiler symbols, and verifies the resulting SKSE release binaries and matching PDBs. This solution uses an optimized Release configuration with debug information rather than CMake's `RelWithDebInfo` name.

The script reads its default source path from `SKSE_SOURCE` in `config.py`. It can be overridden for another checkout:

```powershell
python build-skse.py
python build-skse.py --source-dir <skse-checkout>
python build-skse.py --no-deploy
python build-skse.py --deploy-dir <skyrim-installation>
```

Artifacts are written to `SKSE_BUILD_DIR\Release_VC142\x64`; project intermediates are written below `SKSE_BUILD_DIR\intermediate\Release_VC142\x64`, and progress, status, and temporary MSBuild properties are kept under `SKSE_BUILD_DIR`. The SKSE checkout remains source-only. The checkout's legacy property sheet emits `_1_6_323` and defines the runtime as `0x01061430`, but this wrapper overrides that compile-time value to `0x01064920` (Skyrim 1.6.1170), links the checkout's `skse64.def` export definition, and normalizes the generated runtime file to `skse64_1_6_1170.dll` and its PDB without editing the external checkout. The export definition is necessary because the legacy Visual Studio project omits it even though the runtime requires the `StartSKSE` export; the wrapper verifies that export and refuses to deploy a stripped DLL. These values are intentionally fixed in this helper because this specific checkout is being used for the 1.6.1170 runtime. It also verifies `skse64_loader.exe` and its matching PDB. The checkout's release notes state that `skse64_steam_loader.dll` is no longer needed, so the generated copy is intentionally ignored. By default, deployment copies the runtime DLL/PDB and loader/PDB to `SKYRIM` from `config.py`; `--deploy-dir` overrides that destination and `--no-deploy` disables copying. `.lib` files, the obsolete Steam-loader DLL/PDB, and static-library/helper PDBs are build intermediates or obsolete release outputs and are not deployed. Use the rebuilt loader with the rebuilt runtime DLL; the packaged loader remains available in the checkout as an unmodified reference.

### Packaging path settings

To change automatic deployment, update `DLL_DEPLOY` in both ignored path files. It must name the destination DLL, while `build.py` passes its parent `SKSE/Plugins` directory to CMake:

The post-build step overwrites the deployed DLL after a successful `alchemist` build. The wrapper first configures, builds, and installs the reusable ImGui package at `IMGUI_BUILD_DIR`, then configures the plugin against `IMGUI_INSTALL_DIR`; it also synchronizes the source `locales/alchemist.*.json` resources into the deployed plugin’s `locales` directory. It cleans only plugin outputs and preserves the external CommonLibSSE-NG and ImGui package trees. Because the CMake caches contain machine-specific values, change paths through the ignored configuration files and rerun `python build.py` rather than editing generated files.

### Generated build files

`build-alchemist` contains generated Ninja/CMake files and compiled plugin outputs; it is ignored by Git and must not be edited or committed. The pinned ImGui source configured by `IMGUI_SOURCE_DIR` is built by the source-controlled `cmake/imgui-reusable` wrapper under the external `IMGUI_BUILD_DIR`, and its installed headers, library, and `imgui::imgui` CMake package are under `IMGUI_INSTALL_DIR`. The package is reusable only for the documented Release/x64 MSVC static-runtime DirectX 11 contract; a project with another ABI, runtime, architecture, or backend must use a separate versioned build root. CommonLibSSE-NG's generated CMake files, dependency cache, static library, and installed package are under its external `COMMONLIBSSE_BUILD_DIR` and `COMMONLIBSSE_INSTALL_DIR`. The primary build does not generate solution or project files. If `build.py` finds a cache made by another generator, it replaces that build tree before configuring Ninja. This one-time transition can rebuild dependencies; later builds reuse the configured trees.

To reset the plugin build completely, remove `build-alchemist` and run `python build.py` again. To rebuild the reusable ImGui package, remove the configured external `IMGUI_BUILD_DIR` and `IMGUI_INSTALL_DIR` directories before running the wrapper; do not remove or modify `IMGUI_SOURCE_DIR`. To also rebuild CommonLibSSE-NG and its installed package, remove the configured external `COMMONLIBSSE_BUILD_DIR` and `COMMONLIBSSE_INSTALL_DIR` directories before running the wrapper. To recreate the manifest-specific vcpkg installation, remove only `VCPKG_STATIC_INSTALL_ROOT` and rerun the recorded manifest install command; retain `VCPKG_ROOT\downloads`, `VCPKG_ROOT\binary-cache`, and the old repository-local tree until the new install validates. To reset SKSE, remove only the configured `SKSE_BUILD_DIR` after closing MSBuild, then rerun `python build-skse.py`; do not delete source-tree files unless their generated identity has been established. A complete rebuild can take significantly longer than an incremental build. Old `.vs`, `x64`, or MSBuild tracking directories are obsolete and can be removed after closing any process that has them locked; they are not used by the Python build.

## Troubleshooting

The following reference covers external runtime diagnostics, the build/deployment checks, and the load/crash problems addressed in the current source. Prosperous Alchemist does not create a runtime diagnostic log or a Developer Test Hub log.

### External runtime diagnostics

SKSE and an installed Crash Logger write diagnostics under the Windows user's Documents folder, not the Skyrim installation folder:

```text
%USERPROFILE%\Documents\My Games\Skyrim Special Edition\SKSE\
```

The files of interest are:

```text
skse64_loader.log  # SKSE loader and Skyrim executable version
skse64.log         # SKSE plugin discovery and load status
crash-*.log        # Crash Logger SSE AE VR reports, when installed
```

Use the equivalent paths for the local installation and mod manager:

| Purpose | Path |
| --- | --- |
| Repository root | `<repository root>/` |
| Release build | `<repository root>/build-alchemist/alchemist.dll` |
| MO2 mod source | `<MO2 instance>/mods/Prosperous Alchemist NG/SKSE/Plugins/alchemist.dll` |
| Skyrim installation | `<Skyrim installation>/` |
| Address Library mod source | `<MO2 instance>/mods/Address Library for SKSE Plugins/SKSE/Plugins/` |
| Runtime logs | `%USERPROFILE%/Documents/My Games/Skyrim Special Edition/SKSE/` |

Mod Organizer 2 may virtualize the game's `Data` directory and redirect saves, but the SKSE logs still identify the effective plugin directory and should be checked after each test run. The plugin itself writes no runtime log files.

### Basic diagnostic procedure

1. Exit Skyrim completely.
2. Launch the game through SKSE from the active MO2 profile.
3. Confirm `skse64.log` contains `plugin alchemist.dll ... loaded correctly`.
4. Reproduce the problem once, then close the game and inspect the newest SKSE entries and `crash-*.log` if Crash Logger SSE AE VR is installed.
5. Include the Skyrim runtime, SKSE version, plugin version, and the complete crash report when reporting a problem.

When using MO2, compare the built and deployed DLLs if there is any doubt that the active mod contains the latest build:

```powershell
(Get-FileHash <build path> -Algorithm SHA256).Hash
(Get-FileHash <MO2 mod path> -Algorithm SHA256).Hash
```

The hashes must match.

### CMake cannot find CommonLibSSE-NG

The build expects `COMMONLIBSSE_DIR` to point to an independent CommonLibSSE-NG checkout containing its nested OpenVR checkout. From the external checkout, initialize the complete nested tree and configure again:

```powershell
git -C <external CommonLibSSE-NG checkout> submodule update --init --recursive
```

If the build reports that `openvr.h` is missing from `BSVRInterface.h`, the external nested OpenVR submodule has not been initialized. The recursive command above supplies the required headers and library. If CMake reports that the installed CommonLib package is missing, remove `COMMONLIBSSE_BUILD_DIR` and `COMMONLIBSSE_INSTALL_DIR` and rerun `python build.py` so the wrapper can recreate both trees.

### CMake rejects the vcpkg path

`VCPKG_STATIC_DIR` in the ignored `config.py` must point to a static vcpkg installation containing `share/spdlog/spdlogConfig.cmake`. A CommonLibSSE-NG checkout alone is not sufficient. Install the CommonLibSSE-NG manifest using the `x64-windows-static` triplet, then run `python build.py`. Do not use the old dynamic triplet or copy development DLLs beside the plugin.

### The post-build DLL copy does not occur

The CMake-side copy is configured by `build.py` from the parent directory of `DLL_DEPLOY` in the ignored `config.py`. Update `DLL_DEPLOY` in both ignored path files and run the wrapper again:

```powershell
python build.py
```

If the destination contains an older DLL, compare it with the build output. The wrapper also reports both timestamps, sizes, and SHA-256 hashes in `build.log`:

```powershell
(Get-FileHash build-alchemist/alchemist.dll -Algorithm SHA256).Hash
(Get-FileHash '<MO2 instance>/mods/Prosperous Alchemist NG/SKSE/Plugins/alchemist.dll' -Algorithm SHA256).Hash
```

The hashes should match. Mod Organizer 2 must have the target profile enabled when Skyrim is launched.

### DLL load error `0000007E`

Windows error `0000007E` is `ERROR_MOD_NOT_FOUND`. It means Windows could not load the plugin or one of its imported DLLs. Inspect the Release artifact with:

```powershell
dumpbin /DEPENDENTS build-alchemist/alchemist.dll
```

The current Release build statically links `fmt`, `spdlog`, and the MSVC runtime, so `fmt.dll`, `spdlog.dll`, `MSVCP140.dll`, and `VCRUNTIME140*.dll` should not be required in `Data/SKSE/Plugins`. If any of those third-party libraries appear in the dependency list, the build used the old dynamic vcpkg configuration. Reconfigure from a clean CMake cache using the `x64-windows-static` triplet; do not copy development DLLs into the mod.

### `disabled, fatal error occurred while loading plugin`

This message means the DLL loaded but an exception occurred inside `SKSEPluginLoad`. Check the matching `skse64.log` and any Crash Logger report, then verify that the installed DLL matches the supported runtime and Address Library. The current source passes an empty string, rather than `nullptr`, as the optional REX INI user path.

### Crash when opening the alchemy interface

Install Crash Logger SSE AE VR and reproduce the crash. The report should be taken from:

```text
%USERPROFILE%\Documents\My Games\Skyrim Special Edition\SKSE\crash-*.log
```

The Dear ImGui main window is initialized from the Skyrim D3D11 renderer after the Present hook is installed. The plugin uses Skyrim's native alchemy submenu and also supports SkyUI. If the window remains hidden, confirm that the native crafting menu is open, reopen it after enabling the plugin, and use the external SKSE/crash diagnostics described above if the game crashes.

### Crash after a Developer Test Hub operation

If Crash Logger reports native `CraftingSubMenus::AlchemyMenu` or `IngredientItem` frames after the crafting menu closes, include the Crash Logger report and note the Developer Test Hub operation and menu-close timing. A delayed `skse64` indirect-call access violation with no `alchemist.dll` frame can indicate stale native menu work caused by an active-menu mutation rather than a direct plugin instruction fault. The current implementation runs hub mutations on Skyrim's task interface, coalesces inventory-triggered recalculations during the task, and refreshes the native alchemy submenu after the operation. The Developer Test Hub and cursor workflow remain available while the menu is open.

### The ImGui window stays hidden

- Confirm the native crafting menu is available. If SkyUI is installed, confirm it is enabled in the active profile and that no other UI mod overrides its crafting-menu assets.
- The plugin classifies the active `Crafting Menu` submenu through runtime-matched native RTTI during the menu-open event. It keeps the ImGui window hidden until the native crafting menu and submenu are available; this check is independent of localized display text.
- A failed classification is intentional fail-closed behavior; correct the menu/profile issue and reopen the native alchemy menu.

### No recommendation appears

- Confirm that `alchemist.dll` is in `Data/SKSE/Plugins`.
- Confirm that the game was launched through SKSE.
- Confirm that the installed game runtime is supported by the current Address Library installation.
- Confirm that Address Library provides the version file matching the installed runtime through the active MO2 profile.
- Make sure at least two available, unprotected ingredients share an effect.

### The INI file is not created

The plugin creates `Data/SKSE/Plugins/alchemist.ini` with its default settings when the file is missing. If an existing INI is ignored, confirm its section and setting names and restart the game after editing it.

### Values appear unchanged after editing the INI

The plugin loads settings during startup. Exit the game completely and start it again after changing `alchemist.ini`.

### Custom protection does not work

Ingredient names are matched case-insensitively. You can use the name displayed by the game, an editor ID, or a hexadecimal FormID; separate entries with commas. For example:

```ini
ProtectedIngredients=Daedra Heart|3,Blue Butterfly Wing
```

Entries without a `|count` suffix protect all copies. The in-game Settings page provides ingredient autocomplete and controls for changing each protected amount. The page stores selected ingredients by their displayed names.

## Technical integration

The generated SKSE metadata declares `SKSE::VersionIndependence::AddressLibrary`. Address Library supplies the runtime-specific addresses required by CommonLibSSE-NG, allowing the plugin to use the supported runtime database rather than embedding a separate fixed-address build. This declaration does not remove the requirement to install Address Library.

The native plugin registers a `RE::MenuOpenCloseEvent` sink for the `Crafting Menu` lifecycle and classifies the active submenu through runtime-matched native RTTI. It renders the Prosperous Alchemist main window from a copied recipe snapshot in a D3D11 Present hook. Developer Test Hub inventory, equipment, and modifier operations remain available while the menu is open; each queued game-thread operation updates the player's real state, recalculates the copied snapshot, and refreshes the native alchemy submenu. Inventory-triggered recalculations are coalesced while a hub task is active. The calculation engine does not consume ingredients or craft automatically.

The generated plugin entry points register the plugin with SKSE and the plugin listens for SKSE pre-load-game, post-post-load, data-loaded, and input-loaded messages. Runtime failures are handled by the plugin's existing fail-closed paths and visible Developer Test Hub status messages. Confirmation rows are appended when a complete craft is observed; diagnostic observation CSV output is written only when the corresponding Developer Test Hub export is explicitly invoked.

## Current limitations

- Address Library provides the runtime compatibility layer for supported runtimes, but the matching version library must be installed and the underlying CommonLibSSE-NG/runtime combination must be supported.
- The recommendation snapshot compares the actual native ingredient forms, the protected-ingredient result, tracked player state, and the active CACO calculation revision. Changing only an inventory quantity may not force a new search if those inputs remain unchanged. The master cache is retained in memory for `CacheDurationSeconds` and is not a disk cache.
- Developer Test Hub inventory and equipment changes refresh the overlay's local snapshot and recommendation and then request a native alchemy-menu refresh. Inventory events raised during a hub task are coalesced so the final task refresh is authoritative; the workflow remains available while the menu is open.
- `ProtectedIngredients` uses comma-separated values and does not support commas inside an individual entry.
- Protection names use configured strings and display prefixes use built-in strings; protected ingredients also accept editor IDs and hexadecimal FormIDs. Menu detection uses runtime-matched native submenu RTTI and is not controlled by display text.
- The plugin depends on SKSE, Address Library, Skyrim's native crafting menu and D3D11 renderer, Dear ImGui (linked into the DLL), and the installed runtime. SkyUI is optional.
- The native `CraftingMenu` and active alchemy submenu must be available for submenu classification; otherwise the plugin fails closed and keeps the ImGui window hidden.
- The ImGui main window uses the game's native window and renderer and is intended for Windows Skyrim SE/AE/VR runtimes supported by the checked-out CommonLibSSE-NG version.
- The repository has no automated in-game plugin tests; the deterministic Python prediction harness covers supported exported calculation records, while a successful Release build validates compilation and linking rather than in-game behavior.
