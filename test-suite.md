# Prosperous Alchemist NG - Full Minimal & Comprehensive Test Suite

This document defines the full minimal but comprehensive test suite for Prosperous Alchemist NG. It tests all combinations of ingredient effects, selection orders, modes (`AP`, `Vanilla`, `CACO`, `CACO+AP`), settings (GameSettings, CACO duration index families, AP JSON thresholds/multipliers/overrides/impure cost fix), and player levels/perks/purity filters using a minimal, deterministic set of test blocks.

---

## Overview & Architecture

1. **Two-Tier Configuration Architecture**:
   - **Pre-Launch Disk Setup**: Staged on disk via root Python mode scripts (`pat-ap.py`, `pat-ap-2.py`, `pat-vanilla.py`, `pat-vanilla-2.py`, `pat-caco.py`, `pat-caco-2.py`, `pat-caco-ap.py`, `pat-caco-ap-2.py`) before starting Skyrim. Exit Skyrim before running each Python mode script so disk changes are properly loaded.
   - **In-Game Setting Blocks & Provisioning**: Applied in Skyrim via custom console subcommands (`pat ap`, `pat ap 2`, `pat ap 3`, `pat ap 4`, `pat vanilla`, `pat vanilla 2`, `pat vanilla 3`, `pat vanilla 4`, `pat caco`, `pat caco 2`, `pat caco 3`, `pat caco 4`, `pat caco-ap`, `pat caco-ap 2`, `pat caco-ap 3`, `pat caco-ap 4`).
2. **At Least 2 In-Game Blocks Per Disk Script**:
   Each Python script run on disk hosts at least 2 distinct in-game setting configurations. For example, under `pat-ap.py`, the user executes `pat ap` (Block 1) and then `pat ap 2` (Block 2) in the same Skyrim session.
3. **In-Lab Inventory Refresh**:
   Running any `pat` command inside Skyrim clears existing player ingredient inventory and provisions 99x of each required test ingredient for that specific block. Press **F** while the Alchemy Lab crafting table UI is focused to refresh inventory without exiting the lab.
4. **Chained Mode Flow**:
   Each `pat` command prints craft recipes line-by-line in Skyrim's console and explicitly indicates the next in-game command (e.g. `Next command: run 'pat ap 2'`) or disk step (e.g. `Next step: Exit Skyrim, run 'python pat-ap-2.py'`).
5. **Kryptopyr's Automated Patches & Ingredient Standardization**:
   - `kryptopyr's Automated Patches` (specifically `cc-rarecurios_caco_patch.esp`) standardizes Rare Curios Creation Club content with CACO.
   - It replaces Rare Curios `Aloe Vera Leaves` (`0x0060D0` in `ccbgssse037-curios.esl`) with CACO's native `Aloe Vera` (`0x00A100AD` in `Complete Alchemy & Cooking Overhaul.esp`).
   - Other Rare Curios ingredients (`Comberry`, `Bog Beacon`, `Ambrosia`, `Roobrush`) retain their local FormIDs and are added to CACO formlists via `cc-rarecurios_caco_flm.ini`.
   - **Graceful Provisioning Fallback**: In `ProsperousAlchemistTests.psc`, test ingredient provisioning attempts to resolve CACO's `Aloe Vera` (`0x00A100AD`) first, falling back to Rare Curios `Aloe Vera Leaves` (`0x0060D0`) if CACO or the patch is absent.
   - **Native Plugin & Verification Parity**: `alchemist.dll` and `potion_prediction_test.py` support both ingredient names and FormIDs seamlessly across all modes.

## Phase 0: Pre-Test Setup & CSV Preparation

Before initiating the test suite, preserve the generated observation logs so that the post-test verification can identify the newly captured potions. The plugin owns these files; they are not hand-maintained fixtures.

1. **Preserve Existing Observations (Optional)**:
   If you want a clean capture set, back up the deployed `alchemist.potions-confirmed.csv`, `alchemist.potions-confirmed-all.csv`, and `alchemist.potion-observations.csv` before testing. Do not blank, edit, or script-rewrite these files; they are generated by the plugin and must be regenerated by the in-game export/capture workflow.
2. **Generate New Observations In-Game**:
   Run the requested `pat` blocks and use the Developer Test Hub's explicit CSV export controls or the plugin's normal capture path. The confirmed CSV uses the plugin-generated header beginning with `mode,ingredients,actual_value`; it is not the older `ingredient1,...` schema. After Skyrim exits, the AI validation step reads the newly generated file. The plugin writes complete rows to `alchemist.potions-confirmed-all.csv` and filters duplicate-equivalent rows for `alchemist.potions-confirmed.csv`; diagnostic event data belongs in `alchemist.potion-observations.csv`.
